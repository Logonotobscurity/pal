# Benchmark Execution Blockers — 2026-09-29

## BLOCKER 1 — AfriSwitchCare contract
The dataset is evaluation-only with one test split. The historical loader assumes train/test and speaker_id. Do not execute that path as written.

## BLOCKER 2 — Mock transcription
scripts/benchmark/evaluate-pipeline.ts currently uses mockTranscribe() and explicitly states real provider integration is not implemented.

Therefore any score generated by that path is not a model benchmark.

## BLOCKER 3 — Semantic/action stages are TODO
The evaluator currently marks semantic analysis as not implemented and leaves the downstream workflow/policy/action metrics commented out.

## BLOCKER 4 — Metric scale risk
The evaluator compares code-switch detection against thresholds such as >90 while the result field is initialized as a numeric score without a documented scale. A metric must define whether it is [0,1] or [0,100] and use that scale consistently.

## BLOCKER 5 — Empty-set arithmetic
Aggregate metrics divide by successful_samples without a zero-success guard in multiple places. A failed/non-runnable run must produce status=not_run, not NaN-like or misleading percentages.

## Required resolution
Do not publish benchmark numbers until:
1. dataset contract validation passes;
2. real provider adapters are wired;
3. semantic extraction is implemented;
4. action/policy evaluation is implemented;
5. metric scales and denominators are explicit;
6. raw run artifacts are stored.
